01 / OVERVIEW

Your AI client meets your work in Scrawl.

Scrawl brings notes, task lists, kanban boards, collections, and custom apps together in a single workspace. MCP (Model Context Protocol) enables compatible AI tools to read and update this content through structured tool calls.

For example, your AI client can read a weekly agenda note, locate the right pipeline board, create source-linked cards, and update checklist progress on each card. What people see in the Scrawl interface and what connected tools work with is the exact same source of truth.

Scope of this setup guide
This guide covers the connection model, environment preparation, and verification steps. Official distribution package links, server deployment commands, and client-version-specific menu paths will be added as release packages are finalized.

HTTPS is not a domain extension.
What matters is that your server is reachable over HTTPS with a valid TLS certificate—your domain does not need to end in .com or .net. Note that HTTPS reachability alone does not guarantee compatibility with every cloud client.
03 / LOCAL CONNECTION

Use Desktop with your local AI client.

This setup is designed for working on your personal machine and connecting local MCP tools.

  1. Prepare Scrawl Desktop. Install the official package for your operating system, launch the app, and open your target workspace.
  2. Open your client’s MCP settings. Locate the MCP or tool connection settings inside Codex, Claude Code, or Antigravity. Exact menu names may vary by client version.
  3. Add the Scrawl MCP configuration. Register the extension or MCP server details provided by Scrawl for your version, using the official command, transport type, and credentials.
  4. Review tool permissions. Approve the requested tool permissions in your client. Start with a read-only call that lists workspaces to confirm connectivity.
  5. Verify with a small write operation. Ask your client to create a test note and confirm it appears in Scrawl before moving on to tasks and pipeline boards.

Do not use Scrawl Desktop to expose a direct connection to cloud clients such as ChatGPT.com. For cloud clients, review the Server model.

04 / SERVER & HTTPS

Make your shared workspace reachable.

Scrawl Server is built for team collaboration and remote MCP clients. Before deploying, decide on your server hosting, domain name, and authentication setup.

  1. Prepare the server environment. Configure the supported server package, runtime environment, persistent storage path, and backup policy. Always follow the official deployment instructions rather than unverified images or scripts.
  2. Point your domain. Configure an A, AAAA, or CNAME record with your DNS provider pointing to your server or ingress.
  3. Configure HTTPS. Set up a valid TLS certificate and reverse proxy. Route the official MCP endpoint exposed by Scrawl, ensuring your proxy supports the HTTP transport and long-lived connections required by MCP clients.
  4. Configure authentication. Define user accounts and tool credentials using the access controls supported by your server. HTTPS encrypts traffic in transit; authorization must still be configured explicitly.
  5. Connect your remote client. Use the full HTTPS MCP endpoint URL and authentication method provided by Scrawl. Do not assume the root web URL is the MCP endpoint.
  6. Verify from an external network. Test TLS certificates, sign-in, workspace visibility, and tool calls from outside the host network—starting with read calls, then verifying a test write.
Why aren’t shell commands listed here yet?
Providing copy-paste server commands before the distribution artifact, exact MCP endpoint path, and authentication flow are locked would be misleading. Version-specific deployment commands will be published alongside the release package.
05 / SERVER CAPABILITIES

With your team, in the same workspace.

Core capabilities of the Server edition:

  • Multi-user access: Multiple team members can work inside the shared workspace.
  • Real-time document editing: Edits made to a document appear live for other participants.
  • Per-user permissions: Workspace access is governed by the server’s permission model.
  • Remote MCP access: Compatible local and cloud AI tools can connect over HTTPS.
  • Cloud bot workflows: A bot running in a separate environment can read and update Scrawl as long as the server remains reachable.

Through MCP, workspaces expose user profiles, tool identities, task assignments, and activity history. Specific role names, seat limits, SSO providers, and audit retention windows depend on your server configuration.

06 / CONTINUOUS WORKFLOWS

Server stays online. Your bot triggers the work.

Running automations while your laptop is closed requires two active components: Scrawl Server and the bot or automation service connected to it. Deploying Scrawl Server alone does not create a background bot or scheduler by itself.

  1. Run an MCP-compatible bot or agent in a separate server or cloud environment.
  2. Configure the bot with your Scrawl Server’s verified MCP endpoint and appropriate permissions.
  3. Set up your message, schedule, or webhook trigger on the bot side.
  4. Implement idempotency and error handling in your bot so duplicate messages aren’t processed twice and incomplete inputs are caught cleanly.
  5. Close your computer, send a test trigger, and verify the resulting card or note in Scrawl from another device.

For example, when turning an agenda finding into a pipeline card automatically, make sure the target board, column (e.g., Backlog, Ready for Review, Awaiting Metrics), source note link, and checklist items are specified clearly before saving. You should always be able to inspect and verify bot changes directly inside Scrawl.

07 / FIRST CONNECTION CHECK

Don’t just assume it’s connected. Verify it.

Follow this sequence right after connecting a new AI client to confirm end-to-end MCP tool access:

  1. List workspaces: Confirm the expected workspace appears and select the right space before running actions.
  2. Explore the tree: Check that note, board, and collection names match what you see in the Scrawl app.
  3. Read a note: Confirm the returned content matches the latest version in the app.
  4. Create a test note: Verify the new note appears in the workspace tree (avoid using sensitive production data for tests).
  5. Update a test task or card: Mark a test item complete and verify the state change in the UI.

08 / TROUBLESHOOTING

If your connection isn’t working.

The server opens in a browser, but my AI client cannot connect.

The web UI URL and the MCP endpoint path are typically different. Check the exact MCP URL provided by Scrawl, the transport format expected by your client, your authentication credentials, and external network reachability.

I’m connected, but my workspace doesn’t appear.

Verify that you authenticated as the right user account and that this account has permission to access the target workspace before granting broader privileges.

My bot only responds when my laptop is open.

Your bot process is likely running on your local machine. For 24/7 operation, both Scrawl Server and your bot must run in always-on server or cloud environments.

I can’t find the MCP menu in Antigravity or another client.

Client interfaces change across releases. Check the MCP or tool integration documentation for your specific client version.
